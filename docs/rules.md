# AI 协作规则

本项目使用 Claude Code 辅助开发，遵循以下规则以保障交付质量与可追溯性。

## 1. 技术决策先对齐

- 涉及技术选型（桌面壳、前端框架、托管平台）的决策，**先向用户确认**再实施
- 有明确默认时给出推荐方案（标注「推荐」），避免无谓的往返

## 2. 先验证环境，再定方案

- 动手前探测工具链（Node / Rust / Git 等），技术路线须基于**可实际运行**的环境
- 例如：本机无 Rust 工具链 → 选择 Electron 而非 Tauri

## 3. 小步推进，尽早验证

- 每写完一个模块立即 `tsc --noEmit` 或构建验证，暴露错误越早成本越低
- 核心逻辑（正则、换算、滚动）用**最小可复现脚本**单独验证，而非只看 UI

## 4. 可观测性优先

- 长任务必须有进度反馈与可取消
- 内存等关键指标需**实测数据**支撑，不凭感觉下结论
- 自动化截图 + 文本 dump，用证据而非口头描述证明功能正确

## 5. 诚实记录

- 问题解决记录如实记载「现象 → 根因 → 解决 → 教训」，包括自己的失误（单位换算错、正则边界误用）
- 内存数据区分「主进程（文件处理）」与「全进程（Chromium 基线）」，不夸大、不隐瞒

## 6. 性能敏感处用类型化结构

- 大数组用 `Uint32Array` 而非 JS `Array<number>`（省 10 倍内存）
- 逐字节扫描用 `Buffer`，逐行解码按需 `toString('utf8')`

## 7. 一致性

- 共享类型集中在 `src/shared/types.ts`，main/preload/renderer 三端复用，端到端类型安全
- IPC 通道名集中为常量 `CH`，避免字符串拼写漂移
